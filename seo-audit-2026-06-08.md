# SEO Audit: `fma-website` vs `drsfirst.com`

Audit date: 2026-06-08

Scope:
- Local repo and rendered local build of `fma-website`
- Live comparison site: `https://drsfirst.com`
- Focus: technical SEO, on-page SEO, canonical behavior, sitemap/robots, URL structure, migration safety, schema, and page hierarchy

## Overall Rating

**Current score: 69/100**

This score is for the site exactly as audited from the repo and local rendered build.

If production already sets `NEXT_PUBLIC_SITE_URL` or `SITE_URL` correctly, the effective score would likely move into the **mid/high 70s**. If it does not, canonical and sitemap errors are severe enough to block a safe launch.

## Executive Summary

The local site is structurally stronger than the current live site in some important ways:
- key templates already emit JSON-LD
- the search page is correctly marked `noindex`
- a redirect map exists for several legacy URLs
- provider inventory is larger than the live site

The biggest SEO problems are migration and canonical related:
- rendered canonicals, `robots.txt`, and `sitemap.xml` point to `http://localhost:3000` in the audited environment
- many titles double-append the brand name
- the live services hub is `/service/`, but the new primary hub is `/services`
- several legacy provider URLs still return 404 locally
- the homepage title is weaker than the current live homepage title
- some hub/section H1s are visually branded but not keyword-focused

The site is close enough to become strong, but it is **not launch-ready from an SEO migration standpoint yet**.

## Critical Findings

### 1. Canonicals and crawl files resolve to `localhost`

Observed in rendered local output:
- `/about` canonical: `http://localhost:3000/about`
- `/contact` canonical: `http://localhost:3000/contact`
- `/services` canonical: `http://localhost:3000/services`
- `/location/bowie` canonical: `http://localhost:3000/location/bowie`
- `robots.txt` host: `http://localhost:3000`
- `robots.txt` sitemap: `http://localhost:3000/sitemap.xml`
- `sitemap.xml` URLs all use `http://localhost:3000`

Root cause in code:
- `src/app/lib/config/site.js:15`
- `src/app/robots.js:4`
- `src/app/layout.js:23`

Impact:
- if production env vars are not set correctly, Google would see the wrong canonical host
- the sitemap would advertise non-production URLs
- indexation signals would be diluted or broken

Severity: `P0`

### 2. Titles frequently duplicate the brand

Examples from rendered output:
- `/about`: `About First Medical Associates | Primary Care Across Maryland | First Medical Associates`
- `/contact`: `Contact | First Medical Associates | First Medical Associates`
- `/services`: `Services | Primary Care Doctor at First Medical Associates | First Medical Associates`
- `/location/bowie`: `Top Doctors & Walk-In Clinic in Bowie, MD | First Medical Associates | First Medical Associates`
- `/providers/anita-kunwar`: `Anita Kunwar | Primary Care Doctor at First Medical Associates | First Medical Associates`

Cause:
- global title template appends `| First Medical Associates`
- many page-level titles already include the brand

Implementation references:
- `src/app/layout.js:19`
- `src/app/lib/seo.js:159`
- `src/app/lib/seo.js:166`
- `src/app/lib/seo.js:173`
- `src/app/lib/seo.js:210`

Impact:
- weaker title clarity
- lower CTR potential
- noisy SERP presentation

Severity: `P1`

### 3. The live `/service/` hub changes architecture in the new site

Live site:
- `https://drsfirst.com/service/` is an indexed section hub

New site:
- main services hub is `/services`
- `next.config.mjs` redirects `/service` to `/services`
- but `src/app/service/page.js` still exists and renders a service detail page

Implementation references:
- `next.config.mjs:6`
- `src/app/service/page.js:12`

Impact:
- conflicting intent around the same section root
- migration complexity for a heavily linked and already-indexed live URL
- unnecessary architecture ambiguity

Severity: `P0`

## Priority Fix List

### P0

1. Set and verify the production site URL so canonicals, sitemap, Open Graph URLs, and `robots.txt` all resolve to the real domain.
2. Resolve the `/service` vs `/services` architecture conflict. Pick one canonical hub and remove the contradictory implementation.
3. Add redirects or replacement pages for missing live provider URLs that currently 404.
4. Review every live service URL and map it either to a one-to-one equivalent or a very intentional replacement page.

### P1

1. Remove duplicated brand suffixes from title generation.
2. Rewrite the homepage title and description around primary care, urgent care, Maryland locations, and provider discovery.
3. Rework section hub H1s so they target actual search intent.

### P2

1. Expand local service coverage if those missing live service topics still have search demand.
2. Review patient resource subpages for page-specific H1s and metadata.
3. Validate all legacy live URLs against the redirect list, not just sampled ones.

## Recommended Target State

If you want this to outperform `drsfirst.com`, the target state should be:

- production-domain canonicals everywhere
- no duplicate brand suffixes in titles
- homepage title that matches live search intent or improves it
- one canonical services hub only
- zero legacy SEO URLs returning 404
- one-to-one redirects for every live ranking page possible
- page-specific H1s for all indexable hubs
- complete sitemap parity for the pages you still want indexed

## Bottom Line

The local site has a better technical foundation than `drsfirst.com`, but the current SEO execution is not yet safer than the live site.

Right now:
- `drsfirst.com` still wins on launch safety and keyword continuity
- the local site wins on architecture cleanliness, schema support, and future maintainability

If you fix the canonical host, title duplication, `/service` hub conflict, and missing legacy redirects, this site can surpass the current live site fairly quickly.
